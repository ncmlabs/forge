### Changed
- Slack approval cards now split long approval bodies into multiple Block Kit
  sections, cap oversized cards before Slack's block limit, and include the
  exact Slack API response plus a compact block-payload summary when
  `slack.send_approval` fails. This fixes Gate 2 / Gate 3 `invalid_blocks`
  failures for quote-heavy clone-dev approval bodies (#428).
- Reset the clone-dev playground proof-run guidance around `ncmlabs/forge-playground`
  as a TypeScript proof-run tracker instead of the earlier Rust/Go scaffolds.
  The preflight now verifies the Node app, the repo-local clone-dev config owns
  the TypeScript `test_cmd`, and `#372` is documented as waiting for the clean
  app-specific queue prepared by `#409`.
- Completed the clone-dev proof run against `ncmlabs/forge-playground` for
  issue #372. The recorded run merged playground PR #36 from issue #26 with two
  human approval asks, first-try CI, one review round, and mastery advancing
  from novice to expert. Evidence is recorded under
  `metrics/proof-runs/2026-05-19-run4/`.

### Added
- Gate-3 (merge-PR) config toggle on the dev-cycle reviewer agent (T10.3, #369). Unlike gates 1 and 2, gate_three is not a standalone agent — the merge-PR approval flow already lived inside the reviewer in `workflows/dev-cycle/agents.forge`, so this PR adds a `[gates] merge_pr` boolean (with per-repo override via `[repos."<owner>/<name>"] merge_pr = ...`) plus a missing timeout state machine. **`merge_pr = true` (default):** existing `PostApproval` → `ApprovalResponse` → `skill.github.merge_pr` flow runs unchanged. **`merge_pr = false`:** reviewer auto-merges after the existing knowledge-store consultation (T2.2 still runs), skipping the Slack approval card and posting a `:robot_face: AUTO-MERGED` `PostMessage` confirmation instead. The `auto_reject` early-return preserves knowledge-store rejections on both paths. **Per-repo override** lets sandbox repos opt into auto-merge while production repos keep the gate, both resolved through the same `repo_config_for(...).merge_pr` lookup the reviewer already used for `auto_approve`. **Timeout state machine:** new `timer merge_approval_timeout: 300s` ticks every 5 min while the reviewer is in `awaiting_approval`; at elapsed ≥ 1× `gates.merge_pr_timeout_mins` the reviewer posts a single reminder via `PostMessage`, and at ≥ 2× it emits `WardenEscalation(cause: "merge_approval_2x_timeout")` plus a `:hourglass:` notice and transitions to idle. Cancelled on `ApprovalResponse`. Defaults: `merge_pr = true`, `merge_pr_timeout_mins = 30` — operators must opt out, never the other way around. Surface lives in `src/runtime/clone_dev_config.rs` (`GatesSection.merge_pr`/`merge_pr_timeout_mins`, `RepoOverride.merge_pr`, `CloneDevConfig.gates_merge_pr`/`gates_merge_pr_timeout_mins`, `ResolvedRepo.merge_pr`), `workflows/clone-dev/shared/types.forge` (`RepoConfig.merge_pr`, `CloneDevConfig.gates_merge_pr*`, extended `repo_config_for` fallback), `workflows/dev-cycle/agents.forge` (new `if repo_cfg.merge_pr == false` branch in the reviewer's `on AcceptanceMet` handler, new `on merge_approval_timeout.expired` handler with the 1x/2x cadence, `cancel merge_approval_timeout` added to `on ApprovalResponse`), and `workflows/dev-cycle/clone-dev.toml` (new `[gates]` keys with operator-facing comment). Tests: 5 new unit tests in `clone_dev_config.rs` covering default/authored/per-repo/symmetric-override/serialization paths, plus 6 new integration tests in `tests/clone_dev_gate_three_tests.rs` re-asserting the same surface at the loader-from-disk layer and adding a shipped-config drift guard. Live reviewer + GitHub-CLI behavior is deferred to a follow-up live smoke test mirroring `tests/clone_dev_gate_two_live_smoke.rs`. Carries forward the gate_one/gate_two reserved-keyword landmine: `WardenEscalation` invocation uses `cause` and `detail`, never `reason`.
