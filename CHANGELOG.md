### Added
- Config-driven dev-cycle workdir / branch / commit templates (T8.5, #360). `workflows/dev-cycle/agents.forge` no longer hardcodes the three things that must vary per-org and per-repo: the workdir root, the branch prefix, and the commit message templates (plus the iteration cap and the auto-approve flag). Each agent (planner, implementer, reviewer) loads `CloneDevConfig` on `start` via the existing `config.load_clone_dev` intrinsic (T8.2, #357) and consults `repo_config_for(cfg, repo_slug)` to resolve per-repo overrides — same fallback shape T8.4 used for the knowledge store. The implementer freezes a `{repo_cfg.workdir_root}/{repo_slug}/{issue_id}-{short_id}` workdir on `PlanApproved` and propagates it to the tester and reviewer via new `workdir: Text` fields on `ImplementationReady` and `AcceptanceMet`, so two concurrent invocations sharing a `repo_slug`/`issue_id` (rerun, retry, parallel) can never collide on disk. Commit templates render at runtime through a new `render_commit_message(template, issue_id, title, body, iteration)` pure helper that walks the four supported placeholders (`{issue_id}`, `{title}`, `{body}`, `{iteration}`) via `text.replace` — required because FORGE's `{var}` interpolation is parse-time only, so a string loaded from TOML is otherwise inert. Six new fields on `DefaultsSection` / `RepoOverride` / `CloneDevConfig` / `ResolvedRepo` (`workdir_root`, `branch_prefix`, `commit_template`, `fix_commit_template`, `max_iterations`, `auto_approve`) carry the new knobs; the Rust loader falls back through built-in constants (`/tmp/forge-workdir`, `clone-dev`, `feat({issue_id}): implement per plan`, `fix({issue_id}): iteration {iteration}`, `3`, `false`) so pre-T8.5 TOML files keep working unchanged. Mirror `RepoConfig`/`CloneDevConfig` extensions land in `workflows/clone-dev/shared/types.forge` with corresponding `repo_config_for` defaults. Two new runtime intrinsics ride along — small enough to land in this PR per the #380 precedent: `text.replace(s, find, replacement) -> Text` (registered in `src/resolver.rs` adjacent to `text.to_number`, dispatched in `src/runtime/executor.rs`) is the runtime-side substitution helper; `text.short_id() -> Text` returns the 8-char lowercase hex prefix of a v4 UUID for the workdir collision suffix. A grammar extension adds `\{` and `\}` template escapes (`grammar/forge.pest::template_escape` + `src/parser.rs::decode_template_escape`) so workflow code can pass the literal `"{issue_id}"` placeholder string to `text.replace` without the parser eating it as interpolation — minimal, backward-compatible (no existing source uses `\{`/`\}`). New `bool_to_decision(enabled: Bool) -> Text` pure helper keeps `memory.auto_decision` Text-shaped for downstream observers (debug logs, knowledge-store rows) while letting the config carry the underlying Bool. `branch_name(prefix, issue_id)` signature changes from `branch_name(issue_id)` — the old single-arg form was only called from the planner. New `workflows/dev-cycle/clone-dev.toml` fixture documents the standalone-runner config; production tenants override via `FORGE_CLONEDEV_CONFIG` (the same env-var contract T8.2 set). Tests: 5 new `clone_dev_config` unit cases (`defaults_templating_uses_built_in_constants_when_absent`, `defaults_templating_honors_authored_values`, `per_repo_templating_overrides_defaults`, `per_repo_inherits_built_in_when_defaults_section_absent`, `to_forge_record_emits_templating_fields` — covering the merge ladder + FORGE-record emission); 7 new `tests/text_primitives_tests.rs` cases pinning boundary acceptance + runtime semantics for both intrinsics (substitution, empty-needle no-op, chained template render, hex shape, distinct-on-repeat); 4 new `tests/dev_cycle_workdir_isolation_tests.rs` cases that exercise the DoD bullet 9 — same `issue_id` + different `repo_slug` resolves to distinct paths, per-repo `workdir_root` overrides isolate at root level, same-repo retries diverge via `short_id`, and an end-to-end disk test that creates both candidate dirs and confirms they coexist without collision. The dev-cycle-lesson-smoke and dev-cycle-mastery-smoke examples deliberately stay untouched: they declare their own simplified inline agents to test the learning loop only and don't share code with `agents.forge`, so the new config plumbing isn't reachable from them and the existing examples-validation gate stays green. (#360)

### Fixed
- Per-repo `knowledge_store` scoping (T8.4, #359). Pre-fix, every dev-cycle agent declared `knowledge store: ".forge-knowledge/pr-history"` regardless of repo, so all repos shared one `knowledge.json` file and the reviewer's bare `recall` returned PR-decision lessons from any repo the org had ever processed — a correctness bug, not just tidiness, the moment one process serves multiple repos. Runtime side ships now: `KnowledgeStore::new_scoped(root, project_id, max_entries, retention_days)` resolves persistence to `{root}/{project_id}/knowledge.json` when `project_id` is `Some`, keeps the legacy `{root}/knowledge.json` layout when `None` (the existing 3-arg `new()` is preserved as a thin wrapper, so all ~30 callers stay unchanged); `KnowledgeEntry` gains a `project_id: Option<String>` field with `#[serde(default)]` so existing JSON files deserialize without migration; `add_entry` stamps the store's scope onto every entry written through the learn API while `merge_imported` preserves import provenance; `recall` filters out entries whose `project_id` doesn't match the store's scope as a defence-in-depth layer over path-isolation (handles `merge_imported` contamination and hand-edited JSON). Grammar adds an optional `project_id: <expr>` clause to the `knowledge store:` block (`grammar/forge.pest::knowledge_project_id`); `KnowledgeDecl` gains `project_id: Option<Spanned<Expr>>`; the parser, AST, `extract_knowledge_config` (now a `KnowledgeConfig` struct to keep clippy happy), `agent.rs` runtime path, and `build.rs` server-binary generator all thread the value through — only literal `Text` values resolve at config-extraction time, leaving identifier expressions like `memory.repo_slug` unresolved for T8.5's per-event resolution path. Scoped opens that find a legacy `{root}/knowledge.json` alongside emit a one-line `eprintln!` migration hint pointing at the documented manual `mv`; no auto-migration since legacy files may carry entries from multiple repos. `agents.forge` declarations are deliberately untouched in this PR (T8.5's job, per the issue's "lands alongside T8.5's parameterization" note). Eight new tests pin the user-visible properties: two-projects-isolated end-to-end, scoped writes use `{root}/{pid}/` subdirectory, `None` keeps legacy layout, recall drops mismatched-project entries even when contaminated via `merge_imported`, and the parser accepts both literal and member-access `project_id:` expressions. **Migration:** existing stores at `.forge-knowledge/<root>/knowledge.json` are not seen by scoped agents until manually moved: `mkdir -p .forge-knowledge/<root>/<owner-slug-name> && mv .forge-knowledge/<root>/knowledge.json .forge-knowledge/<root>/<owner-slug-name>/knowledge.json`. Legacy entries that mix multiple repos cannot be losslessly auto-attributed; pick a default org or rebuild the store. (#359)

### Added
- Stage-2 deterministic label routing for the clone-developer assembly (T8.3, #358). New `workflows/clone-dev/stage2/label_router.forge` is a pure FORGE task that takes a GitHub-issue label list plus a typed `LabelRouting` (namespace + parallel suffix→target arrays + triage_target) and returns a `RoutingDecision` — zero LLM calls, zero skill calls, p99 well under the 5ms acceptance budget. The mastermind's `on GithubIssueOpened` handler now extends to a `labels: Text[]` parameter, calls the router, emits a new `TaskRouted(task_id, specialist, repo, issue_id, outcome, matched_suffix, diagnostic)` event, and gates the existing `CloneDevInbound` fan-out on `decision.outcome == "routed"` so the LLM-classification path runs only for direct API or Slack inbound. Routing rules (in priority order): zero `<namespace>:*` labels → `triage_specialist` (`no_clonedev_label`), >1 such labels → `triage_specialist` (`multi_clonedev_labels`), suffix mapped in `[labels.routing]` → that specialist (`ok`), unmapped suffix → `triage_specialist` (`unknown_suffix:{suffix}`). Suffix→target is config-driven via `clone-dev.toml` `[labels.routing]` (e.g. `plan = "planner"`, `impl = "implementer"`, ..., `ops = "release_manager"`); adding a new specialist is a one-line config change with no FORGE code edit. New `triage_specialist` stub agent (`workflows/clone-dev/stage2/triage_specialist.forge`) subscribes `TaskRouted where specialist == "triage_specialist"`, logs the diagnostic, and posts a `:mag: clone-dev triage needed for ...` message via the existing slack_adapter — no LLM, no skills. The Rust loader (`src/runtime/clone_dev_config.rs`) gains `LabelsSection.namespace`/`triage_target`/`routing` (BTreeMap → deterministic order), `CloneDevConfig.label_routing_namespace`/`label_routing_suffixes`/`label_routing_targets`/`label_routing_triage_target` flat sibling fields (FORGE record-of-record is untested today per `types.forge:154–158`, so suffix/target are parallel `Text[]` arrays the pure task rebuilds into a typed `LabelRouting` via `label_routing_of(cfg)`), and a back-compat default of `"triage_specialist"` for older TOML files lacking the new keys. `RoutingDecision.diagnostic` and `TaskRouted.diagnostic` use the name `diagnostic` rather than `reason` because `reason` is the FORGE LLM-call keyword. Field comments inside `type` / `event` blocks are not yet supported by the parser, so explanatory comments live above each declaration. `org_warden manages [...]` adds `triage_specialist` (10 agents total, was 9). New `clone-dev.toml.example` `[labels]` block documents the namespace + per-suffix mapping with inline comments. The mastermind handler header carries this divergence as a code comment so future readers find it.
